# fsai_vehicle_interface

ROS 2 hardware abstraction layer (HAL) for the IMechE Formula Student AI **ADS-DV** vehicle.

This package sits between the autonomous software stack and the vehicle CAN bus. It wraps the FS-AI C API library (vendored internally), publishes all VCU sensor data as standard ROS 2 topics, and forwards drive commands from the stack to the VCU — managing the full ADS-DV mission handshake state machine automatically.

```
┌─────────────────────────────────────────────────────────┐
│                   Autonomous Stack (Python)              │
│  perception │ planning │ control                         │
└───────────────────────┬─────────────────────────────────┘
                        │ ROS 2 topics (DDS / FastRTPS)
┌───────────────────────▼─────────────────────────────────┐
│              fsai_vehicle_interface (this pkg)           │
│  VehicleInterfaceNode  +  StateMachine  +  FS-AI API    │
└───────────────────────┬─────────────────────────────────┘
                        │ SocketCAN (can0 / vcan0)
┌───────────────────────▼─────────────────────────────────┐
│                    ADS-DV VCU (CAN bus)                  │
└─────────────────────────────────────────────────────────┘
```

## Features

- **Self-contained** — vendors the FS-AI_API C source files internally; no dependency on the `FS-AI_API` repository on the build machine.
- **Plug-and-play** — drop the folder into `fsai_ros2_ws/src/`, add four message definitions to `fsai_interfaces`, and `colcon build`.
- **100 Hz main loop** — reads VCU/IMU/GPS data, publishes all topics, and sends actuator commands in one deterministic loop.
- **Full state machine** — implements the complete ADS-DV handshake (WAIT_FOR_VCU → WAIT_FOR_MISSION → MISSION_SELECTED → WAIT_FOR_GO → DRIVING → FINISHING → FINISHED) with emergency handling and VCU power-cycle recovery.
- **Safety-first design** — stale command detection zeros all actuator outputs if the stack stops publishing; destructor sends 20 zero-frames on node shutdown.
- **Python-transparent** — all interfaces are standard ROS 2 topics; the Python stack uses the same message types generated by `rosidl` without any C/C++ knowledge.

## Messages to transfer to `fsai_interfaces`

This package depends on four custom message types that must live in the `fsai_interfaces` package (the shared message package for the MDX FSAI stack).

**Before building**, copy all four `.msg` files from `messages_for_fsai_interfaces/` into `fsai_interfaces/msg/` and register them in `fsai_interfaces/CMakeLists.txt`:

```bash
# From the repo root (fsai_ros2_ws/src/)
cp fsai_vehicle_interface/messages_for_fsai_interfaces/*.msg \
   fsai_interfaces/msg/
```

Then in `fsai_interfaces/CMakeLists.txt`, add the four messages to the `rosidl_generate_interfaces()` call:

```cmake
rosidl_generate_interfaces(${PROJECT_NAME}
  # ... existing messages ...
  "msg/DriveCommand.msg"
  "msg/VcuStatus.msg"
  "msg/WheelSpeeds.msg"
  "msg/InterfaceState.msg"
  DEPENDENCIES std_msgs
)
```

Rebuild `fsai_interfaces` first so the generated headers are available when building this package.

### Message summary

| Message | Description |
|---|---|
| `DriveCommand` | Actuator command from stack to vehicle interface (steer, speed, torque, brake) |
| `VcuStatus` | Full VCU status (AS state, AMI state, faults, shutdown cause) |
| `WheelSpeeds` | Four-wheel RPM and pulse counts |
| `InterfaceState` | Internal state machine state (WAIT_FOR_VCU → FINISHED / EMERGENCY) |

## CAN Bus Setup

### Real ADS-DV vehicle (can0)

```bash
# Bring up the CAN interface at 500 kbps (ADS-DV standard)
sudo ip link set can0 up type can bitrate 500000

# Verify
ip -details link show can0

# Optional: monitor all frames
candump can0
```

The `can0` interface must be up **before** launching the node. The node calls `fs_ai_api_init("can0", 0)` on startup and throws a `std::runtime_error` if it fails.

### Virtual CAN for simulation / bench testing (vcan0)

```bash
# Load the vcan kernel module (once per boot)
sudo modprobe vcan

# Create and bring up vcan0
sudo ip link add dev vcan0 type vcan
sudo ip link set vcan0 up

# Launch the node with vcan0
ros2 launch fsai_vehicle_interface vehicle_interface.launch.py can_interface:=vcan0
```

When using `vcan0`, no VCU frames will arrive so the state machine stays in `WAIT_FOR_VCU`. You can inject test frames with `cansend` from `can-utils`.

## Topics Reference

### Subscribed topics (inputs from the autonomous stack)

| Topic | Type | Description |
|---|---|---|
| `/vehicle/drive_command` | `fsai_interfaces/DriveCommand` | Actuator setpoints. Only forwarded to CAN when state is `DRIVING` and command is fresh. |
| `/vehicle/mission_complete` | `std_msgs/Bool` | Publish `true` once to signal mission finished. Triggers `FINISHING` state. |
| `/vehicle/estop` | `std_msgs/Bool` | Publish `true` to trigger EBS immediately (latched — cannot be un-triggered without a VCU power cycle). Required for Static Inspection B, Autonomous Demo end sequence, and rule T4.2.2 sensor loss handling. |

### Published topics (outputs to the autonomous stack)

| Topic | Type | Rate | Description |
|---|---|---|---|
| `/vcu/status` | `fsai_interfaces/VcuStatus` | 100 Hz | Full VCU status: AS state, AMI state, faults, shutdown cause |
| `/vcu/wheel_speeds` | `fsai_interfaces/WheelSpeeds` | 100 Hz | Four-wheel RPM and ABS pulse counts |
| `/vcu/steering` | `std_msgs/Float32` | 100 Hz | Actual steering angle [deg] from VCU |
| `/vcu/brake` | `std_msgs/Float32MultiArray` | 100 Hz | Brake pressures [bar]: [front_left, front_right, rear_left, rear_right] |
| `/vcu/imu` | `sensor_msgs/Imu` | 100 Hz | IMU data (linear accel m/s², angular vel rad/s). Covariance matrices set to −1 (unknown). |
| `/vcu/gps` | `sensor_msgs/NavSatFix` | 100 Hz | GPS fix (decimal degrees lat/lon, altitude m) |
| `/vehicle/interface_state` | `fsai_interfaces/InterfaceState` | 100 Hz | Current state machine state. Use this to know when driving is safe. |

## State Machine

```
                 ┌──────────────────┐
   (startup)────►│  WAIT_FOR_VCU    │ No CAN frames from VCU yet
                 └────────┬─────────┘
              VCU frames arrive (can_stats count > 0)
                          │
                 ┌────────▼─────────┐
                 │ WAIT_FOR_MISSION  │ VCU alive, operator selects mission on touchscreen
                 └────────┬─────────┘
              AMI_STATE ≠ NOT_SELECTED
                          │
                 ┌────────▼─────────┐
                 │ MISSION_SELECTED  │ AI signals MISSION_SELECTED to VCU
                 └────────┬─────────┘
                   AS_STATE == AS_READY (VCU armed, 5s timer)
                          │
                 ┌────────▼─────────┐
                 │  WAIT_FOR_GO     │ AI signals MISSION_SELECTED; waiting for RES GO
                 └────────┬─────────┘
                   AS_STATE == AS_DRIVING (operator presses GO on RES)
                          │
                 ┌────────▼─────────┐
                 │    DRIVING       │ AI signals MISSION_RUNNING; drive commands forwarded
                 └────────┬─────────┘
              /vehicle/mission_complete = true
                          │
                 ┌────────▼─────────┐
                 │    FINISHING     │ AI signals MISSION_FINISHED; waiting for VCU ack
                 └────────┬─────────┘
                   AS_STATE == AS_FINISHED
                          │
                 ┌────────▼─────────┐
                 │    FINISHED      │ Full VCU power-cycle required before next run
                 └──────────────────┘

Any state ──► EMERGENCY if AS_STATE == AS_EMERGENCY_BRAKE
FINISHED / EMERGENCY ──► WAIT_FOR_MISSION if AS_STATE == AS_OFF and AMI == NOT_SELECTED
  (operator turns off LV Master → ASMS → TSMS, then powers back up)
```

### What to send to the AI2VCU frame

| State | MISSION_STATUS | DIRECTION_REQUEST | Drive commands |
|---|---|---|---|
| WAIT_FOR_VCU | NOT_SELECTED | NEUTRAL | Zeroed |
| WAIT_FOR_MISSION | NOT_SELECTED | NEUTRAL | Zeroed |
| MISSION_SELECTED | SELECTED | NEUTRAL | Zeroed |
| WAIT_FOR_GO | SELECTED | NEUTRAL | Zeroed |
| DRIVING | **RUNNING** | FORWARD | Forwarded (if fresh) |
| FINISHING | FINISHED | NEUTRAL | Zeroed |
| FINISHED | FINISHED | NEUTRAL | Zeroed |
| EMERGENCY | NOT_SELECTED | NEUTRAL | Zeroed |

> **Critical**: Sending `SELECTED` when the VCU expects `RUNNING` raises a `MISSION_STATUS_FAULT` and triggers `SHUTDOWN_CAUSE=8`. The state machine handles this correctly.

## Python Stack Integration

Because this package exposes **standard ROS 2 topics**, the Python autonomous stack requires **no changes** to interface with it. ROS 2 uses DDS (FastRTPS) as middleware — nodes written in C++ and Python communicate transparently over the same topic bus.

The `rosidl` build tool generates Python bindings from the `.msg` files automatically. After building the workspace, any Python node can import and use the messages:

```python
import rclpy
from rclpy.node import Node
from fsai_interfaces.msg import DriveCommand, InterfaceState

class ControlNode(Node):
    def __init__(self):
        super().__init__('control_node')

        # Know when it is safe to send drive commands
        self.create_subscription(
            InterfaceState,
            '/vehicle/interface_state',
            self.state_callback,
            10
        )

        self.drive_pub = self.create_publisher(DriveCommand, '/vehicle/drive_command', 10)
        self.driving = False

    def state_callback(self, msg: InterfaceState):
        self.driving = (msg.state == InterfaceState.DRIVING)

    def send_command(self, steer_deg: float, speed_rpm: float, torque_nm: float):
        if not self.driving:
            return   # not safe yet — state machine will handle it
        cmd = DriveCommand()
        cmd.header.stamp = self.get_clock().now().to_msg()
        cmd.steer_angle_deg = steer_deg
        cmd.axle_speed_rpm  = speed_rpm
        cmd.axle_torque_nm  = torque_nm
        cmd.brake_pct       = 0.0
        self.drive_pub.publish(cmd)
```

Signal mission complete:

```python
from std_msgs.msg import Bool

done_pub = node.create_publisher(Bool, '/vehicle/mission_complete', 1)
done_pub.publish(Bool(data=True))
```

Check VCU faults:

```python
from fsai_interfaces.msg import VcuStatus

def vcu_callback(msg: VcuStatus):
    if msg.mission_status_fault:
        node.get_logger().error("VCU raised MISSION_STATUS_FAULT (SHUTDOWN_CAUSE=8)!")
    if msg.ebs_fault:
        node.get_logger().error("EBS fault!")
    # msg.as_state values: 0=AS_INIT, 1=AS_OFF, 2=AS_READY,
    #                      3=AS_DRIVING, 4=AS_EMERGENCY_BRAKE, 5=AS_FINISHED
```

## Known Limitations

1. **Fault bits** — `fs_ai_api_vcu2ai` does not expose the individual fault flags from the `VCU2AI_Status` CAN frame (bytes 4–5). All fault fields in `/vcu/status` are published as `false`. If the FS-AI API is updated to expose these, add them to `publish_vcu_status()` in `vehicle_interface_node.cpp`.

2. **GPS accuracy** — The FS-AI GPS data provides position only (lat/lon/alt). No velocity, heading, or HDOP is available from the API struct. `NavSatFix.position_covariance_type` is set to `COVARIANCE_TYPE_UNKNOWN`.

3. **Single node** — The package runs as a single executable. If the CAN interface goes down mid-run, the API background thread will stop delivering data but the node will not crash — it will continue publishing stale data and the state machine will not advance. A watchdog on `VCU2AI_Status_count` increment rate can be added if needed.

4. **No re-init on CAN failure** — `fs_ai_api_init()` is called once in the constructor. CAN interface failure after startup is not handled; restart the node.

5. **IMU calibration** — The ADS-DV IMU raw data is in milli-g and deg/s. The conversions applied (×9.80665/1000, ×π/180) are standard but no bias correction or calibration is applied.
